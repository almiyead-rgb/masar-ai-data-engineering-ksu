# Program and learning outcomes

**Modern Data Engineering for AI Systems (SDA-DSC-214)**

Build one cumulative Mini-Lakehouse across five evenings. Run your labs in Google Colab, compare your results, and save your progress to GitHub every day.

## Outcomes

1. **LO1:** Compare warehouses, data lakes and Lakehouse architectures for a stated use case.
2. **LO2:** Explain compute–storage separation and its effects on cost, elasticity and scale.
3. **LO3:** Design an ELT pipeline for a modern cloud data environment.
4. **LO4:** Implement Delta Lake tables with ACID transactions and schema enforcement.
5. **LO5:** Develop streaming and event-driven ingestion patterns.
6. **LO6:** Apply data-quality, observability and governance controls across a pipeline.
7. **LO7:** Connect Lakehouse products to AI, reporting and analytics consumers.
8. **LO8:** Build a working Mini-Lakehouse with Delta Lake and PySpark.

## Delivery

Five evenings, 17:00–21:00 in Asia/Riyadh. Each day includes 150 minutes of explanation, demonstrations and a quick activity; 60 minutes of project work including the daily question and saving; and two 15-minute prayer breaks. Total scheduled attendance is 20 hours; net learning time is 17.5 hours. Course dates and exact prayer-break positions are confirmed by the instructor.

The course has exactly 100 slides, 20 per day. Slides 9–10 contain the activity and its answer. Slides 19–20 contain the lab question and its answer. Labs 01–08 are stages of one cumulative project and do not create an additional final assignment.

## Scope and preparation

You use Google Colab for execution and your own GitHub repository for daily code and evidence. Basic Python and SQL familiarity helps; the guided route explains the key operations before you run them. The original supplied reference describes a specialist program. This course provides guided delivery for the cohort without claiming that a short local exercise demonstrates production-scale competence.

You work with real PySpark, Delta Lake, dbt, Kafka and Great Expectations components on the fixed synthetic data. You compare architectures and cost assumptions, build ELT, manage transactions and corrections, ingest events, apply quality/governance controls, and consume the final products. AI serving means preparing and consuming suitable historical features; training a model is outside this dataset's supervised-label scope.

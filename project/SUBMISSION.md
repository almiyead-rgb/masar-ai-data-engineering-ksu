# Submit your cumulative project

Submit the same project you have built over all five days. Your repository should show the daily progression, your own executed notebooks, your explanations and the final results.

## 1. Check your repository

- Your fork contains the five executed daily notebooks in their original `dayNN/STUDENT.ipynb` paths.
- Your notes include all eight `student/dayNN/LABxx_NOTES.md` files and five `student/dayNN/REFLECTION.md` files with your own daily answers and observed evidence.
- Your code/SQL changes, architecture decisions, `student/BENCHMARKS.md`, `student/DECISIONS.md` and `student/GOVERNANCE.md` are present.
- Small stage reports and final CSV exports can be inspected without downloading a large runtime cache.
- Your `student/PROJECT_README.md` explains the business problem, technical architecture, run order, results and limits. Add a prominent link to this file from your repository's root `README.md`. Use [the template](../templates/PROJECT_README.md).
- Your final handoff archive is retained in Drive. Provide its link privately if the instructor requests it, with access that allows the reviewer to read it.
- You have removed credentials, real personal data, package caches and broker logs from public files.

## 2. Identify the exact version

Complete [the submission metadata template](../templates/submission.json) with your repository URL, submitted branch and final commit SHA. Use your chosen public display name in public metadata. Any student number or private identity confirmation belongs in the organizer's private submission channel.

Open the repository URL while signed out or in a private window if it is intended to be public. Check the submitted branch and notebook outputs. If your repository is private, verify reviewer access through the organizer's process before the deadline.

## 3. Include the course credit

In `student/PROJECT_README.md`, name **Modern Data Engineering for AI Systems (SDA-DSC-214)** and **SDAIA Academy**, link to [the Academy's GitHub](https://github.com/SDAIAAcademy), and include `#SDAIAAcademy`. Preserve attribution to reused course material by **Meaad Al-Marri** and the [original Masar repository](https://github.com/almiyead-rgb/masar-modern-data-engineering).

Suggested acknowledgement:

> Developed as part of Modern Data Engineering for AI Systems (SDA-DSC-214), using course materials by Meaad Al-Marri. SDAIA Academy: https://github.com/SDAIAAcademy. #SDAIAAcademy

Explain your own implementation immediately after the acknowledgement. This requirement concerns your README and submission message; it does not require a social-media post.

## 4. Send the submission through the private course channel

The instructor announces the channel and final deadline in Asia/Riyadh time. Until those details are announced, saving a project to GitHub does not by itself notify the instructor.

Include:

- Repository URL.
- Submitted branch, normally `main`.
- Final commit SHA.
- Any requested private artifact link.
- A brief note identifying a known limitation or unfinished stage, if any.
- `#SDAIAAcademy`.

Do not post your attendance record, mark or private identifiers as a public GitHub issue. No pull request to the instructor's course repository is required.

## 5. Understand the result

Your project is marked out of 100 using [the rubric](../assessment/RUBRIC.md). Attendance on all five days plus a score of at least 70 earns a completion/pass certificate. All five days without a project or with a score below 70 earns an attendance certificate only. Submitted projects remain pending until assessed. Review [the full policy](../assessment/CERTIFICATES.md).

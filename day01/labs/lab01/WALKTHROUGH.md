## Goal and scope

Preserve what arrived, identify its source and delivery, and read it back from a real Delta table. Do not clean city labels or deduplicate business trips yet. This is part of the same final project, not an additional assignment.

Open [source inspection](../../STUDENT.ipynb). The base files contain 72 trips, 6 drivers and 216 event lines. A file hash detects a changed payload; it does not prove business accuracy or privacy compliance.

## 3 · Read without cleaning

The CSV columns are strings at this stage; original timestamp offsets remain visible. Event lines are stored as `raw_json`, not yet expanded or streamed. `DataFrame` describes a computation; actions such as `count()` or a write trigger work. See the [Spark CSV documentation](https://spark.apache.org/docs/3.5.8/sql-data-sources-csv.html).


## 4 · Add delivery metadata and append

The shared function adds `_source_file`, `_source_sha256`, `_batch_id` and `_ingested_at`. Ingestion time is generated by Spark in a UTC-configured session; it is not trip event time. The first delivery is `base_001`. Each table has its own Delta transaction; this is not one atomic transaction across three tables. Inspect [the shared implementation](../../../src/masar/bronze.py) and [Delta writes](https://docs.delta.io/delta-batch/).

```python
from masar.bronze import ingest_feed
for feed in ("trips", "drivers", "gps_events"):
    print(ingest_feed(spark, SOURCE, WORK, feed, "base_001"))
```

## 5 · Distinguish a redelivery from a new business trip

Intentionally deliver the same trip file under a new batch identifier. Expected Bronze trip rows become 144, while expected distinct business trips stay 72. Drivers and events remain 6 and 216. A repeated call using the same batch identifier is rejected in this single-writer lab. That guard is not a distributed exactly-once guarantee; downstream Silver handles the business-key policy.

```python
print(ingest_feed(spark, SOURCE, WORK, "trips", "replay_002"))
```

## 6 · Verify the table, not just a success message

The verification reads real tables, checks each batch against raw values, inspects non-empty Delta logs and data files, and rereads the initial 72-row snapshot. It requires the expected metadata, totals and business-key count. No report is marked successful before these checks finish. See [Delta readback and versioned reads](https://docs.delta.io/quick-start/).

```python
from masar.bronze import verify_bronze
from masar.workspace import record_bronze_success
```
